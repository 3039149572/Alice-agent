# Alice Agent v0.9.3 — 主动重试、每日事件时段与诊断

与AstrBot解耦的角色Agent：AstrBot提供平台、模型和生命周期，Core管理事件、状态、记忆与决策。本版在v0.9.1上修复检索、媒体并发、超时回退和交付一致性，增加用户记忆管理及诊断。关系计算规则、角色设定、小说资料和对白触发规则保持原样。

v0.9.3修正Jev技术失败后事件无法重试、夜间每日事件可能调用模型和日志原因混淆的问题。v0.9.2已合并此前未发布、曾标记为0.10.0的本地修复。真实模型中文校准、QQ送达/播放仍需验收；发布不代表服务器已重载。进度和验证证据见 [REPAIR_PROGRESS.md](docs/REPAIR_PROGRESS.md)，开发交接见 [HANDOFF.md](HANDOFF.md)。

源码仓库：[3039149572/Alice-agent](https://github.com/3039149572/Alice-agent)。本版声明AstrBot `>=4.28.1,<5`；当前本机与CI基线为4.28.1，未承诺所有未来4.x版本均通过实测。媒体素材和实例数据独立部署。

## 本版行为

- Jev技术失败后释放事件占位，默认60秒起指数退避、最多等待900秒；调用尝试次数不退还，仍受当日上限约束。重启保留重试时间，过期占位可恢复；有效拒发不会按技术失败重试。明确跟进技术失败最多尝试三次，仍受跟进有效期约束。
- 每日事件的新生成及相关模型调用仅在配置的主动时段内开始，普通聊天读取当天已有缓存不调用事件模型。跨时段重新检查，跨日未完成批次不会写回旧日期；当日概率不因重试重新抽签。
- 旧版已尝试记录缺少失败类型，升级不会清零计数、重抽概率或自动推翻旧拒发。旧记录当天保持原状态，新日期及新产生的尝试采用新流程；详见 [重试与时段说明](docs/PROACTIVE_RETRIES.md)。
- 默认将主动判断、未发送原因、模型规划及发送结果写入插件数据目录的 `proactive_today.log`。同日追加、重启保留，按服务器本地日期跨日覆盖；后台循环关闭时仍记录开关状态并检查换日。详见 [当日诊断文件](docs/PROACTIVE_LOG.md)。
- 中文索引覆盖范围内全部历史，通用话题不能让无关记忆通过门槛。`local_memory_candidate_limit` 表示分批读取数量。
- 明确的当前用户自述可生成有限类型事实，保留来源与替代版本，重复陈述合并来源，迟到旧陈述不覆盖当前事实。引述、疑问、假设、历史、未来计划和角色扮演不自动写为当前事实。
- 生成总预算默认60秒；每条模型回退链共用原30秒预算，主模型为备用模型留出时间。媒体默认最多等待12秒，同时发送文字和语音时先发文字。
- 同一Genie地址和角色的参考设置与合成互斥，生成文件分别持有。会话历史只记录实际发送的文字/实际配音原文，分段中断只记录前缀。
- 已交付回复的本地写入可以恢复，不重复累加状态、关系计数、访问次数和主动冷却；恢复不重发消息。平台送达与意图落盘之间仍有明确边界，见数据治理文档。
- Jev可按任务配置模式和门槛，汇总指标按日期/模型/模式/任务分组。默认关闭数值情绪干预；该默认变化不改变关系Reducer或角色设定。
- 消息合并、媒体交付和本地提交协调分别有独立模块；发布流程先检查、测试解包产物，再允许创建Release。

## 私聊命令

| 命令 | 用途 |
|---|---|
| `/alice-status` | 只读查看自己的主动候选、评分、已有抽签、拦截原因和后续条件；不重新抽签或主动发送。 |
| `/alice-data list [页码]` | 查看自己的当前记忆ID与内容。 |
| `/alice-data journal [页码]` | 查看范围内原始轮次。 |
| `/alice-data show ID` | 查看内容、版本、来源及编辑历史。 |
| `/alice-data correct ID 新内容` | 更正原句或同类型的当前事实。 |
| `/alice-data delete ID` | 预览删除记忆及其事实版本/来源。 |
| `/alice-data clear-memory` | 预览清空自己的范围内记忆与原始轮次。 |
| `/alice-data confirm 确认码` | 5分钟内、同一用户和会话、单次确认；数据变化须重新预览。 |

纠错/删除还会清空相关近期上下文与派生文字缓存。关系与情绪数值、主动预算/冷却、小说静态知识和迁移备份保留。命令不接受其他用户ID，不调用模型。完整语义与保留边界见 [DATA_GOVERNANCE.md](docs/DATA_GOVERNANCE.md)。

## 新配置

| 配置 | 默认 | 含义 |
|---|---:|---|
| `turn_timeout` | 60 | 生成计算总预算，秒。 |
| `llm_provider_attempt_timeout` | 15 | 有备用模型时单Provider尝试上限，秒。 |
| `llm_fallback_reserve_seconds` | 5 | 在原链路总预算内为备用模型预留时间。 |
| `media_text_first` | true | 同时要求文字和语音时先发文字。 |
| `media_render_timeout_seconds` | 12 | 翻译、锁等待、Genie初始化/合成的上限。 |
| `memory_fact_extraction_enabled` | true | 保守提取明确自述，不新增模型请求。 |
| `memory_retention_days` | 0 | 长期记忆保留天数；0保留，固定记忆跳过。 |
| `memory_journal_retention_days` | 0 | 原始轮次保留天数；0保留。 |
| `memory_inactive_fact_retention_days` | 0 | 失效事实版本保留天数；0保留。 |
| `jev_affect_intervention_enabled` | false | 是否允许Jev数值混入最终情绪。 |
| `jev_task_policies` | `{}` | 按任务覆盖mode/auto_threshold/review_threshold的JSON。 |
| `proactive_retry_base_seconds` | 60 | 技术失败后的首次重试等待，秒。 |
| `proactive_retry_max_seconds` | 900 | 指数退避等待的上限，秒。 |

保留清理独立于主动循环和诊断开关；近期快照也按原72小时默认期限清理。所有配置以 `_conf_schema.json` 和实际构建函数为准，已有实例显式配置优先于默认值。

## 升级与验证

旧库迁移前自动建立可读备份；回退必须停止插件并使用对应旧库备份，不能直接用旧检索逻辑读取新事实版本库。详见 [升级步骤](SERVER_UPDATE.md)、[前一批可靠性修复](docs/RELIABILITY_BATCH.md) 和 [发布检查](docs/RELEASE_CHECKS.md)。

本地测试使用模拟Provider/平台、临时真实SQLite和HTTP模拟传输；中文评估脚本只评估已有预测，默认跳过尚未审核的10条样例，不构成模型质量证明。

原有主动概率、角色知识与媒体配置说明分别见 [主动消息](docs/PROACTIVE.md)、[小说上下文](docs/NOVEL_CONTEXT.md)；[v0.9.1完整README](docs/README_V0_9_1.md) 仅作历史参考，冲突处以本版说明和当前源码为准。
