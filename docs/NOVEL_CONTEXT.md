# 小说角色知识与对白参考（本地 v0.9.0）

默认扮演整合骑士爱丽丝·辛赛西斯·萨提，没有童年滋贝鲁库的亲历记忆。别人告诉她的童年故事可以了解，但读者知识、名字熟悉感、情感触动和转述都不能变成记忆恢复。角色身份、性格、说话方式以及 Planner、Response、主动行为、每日事件提示均已按这个边界调整。

## 采用的资料

来源为用户提供的 `爱丽丝LLM上下文资料包_全章覆盖版.zip`，原小说 TXT 哈希、归属、阶段和证据行号保存在 `alice_agent/knowledge/data/source_manifest.json`。未导入原小说全文、逐章全量梗概、补篇、未确定事项或作者／译者评论。

| 数据 | 原资料 | 采用 | 默认可参与检索 |
| --- | ---: | ---: | --- |
| 对白示例 | 172 | 28 | 骑士阶段13条；后期15条默认禁用 |
| 剧情与关系卡 | 245 | 228 | 骑士阶段89张；童年44张只作读者背景；后期95张默认禁用 |

对白逐条选用了具体主题或细粒度触发语，例如“资源不足／目前上限”“预留物品／紧急备用”“具体是哪位”“反抗公理教会”。“关心、解释、确认、日常聊天”等宽泛 tag 不用于召回，没有合适示例就返回空结果，不凑满数量。原标签仅留作来源注释和保守排除条件，不作为泛化路由，也不放进给回复模型的示例上下文。

童年对白、执法威胁对白、仅有宽泛标签的对白和归属不明条目不纳入示例。另排除了标为调侃但实际说“在被我杀掉之前……”的手帕台词，以及缺乏具体表达内容的确认句。片段中出现的原受话者不等于当前用户，调侃示例还要求真实聊天已建立一定熟悉程度；手工标注的 `use_for_actions` 与本轮 Planner action 必须兼容。

剧情卡的通用 tag 不参与评分，只用具体文本、人物实体及主题限制。亲历、明确听闻和读者背景分别保留；童年卡即使原始标注为童年人格亲历，也统一转为当前骑士人格的 `reader_background`，不能冒充现有自传。骑士时期听别人讲童年的场景，亲历的是当时的谈话与反应，不是童年事件本身。

核对原文修正了 `full-h075440-b004-f01` 的标题：贝尔库利此处是在冻结术式中短暂苏醒，不是其后来战死的场景。原资料包保持原状，修正在导入结果和清单中注明。

## 生成时的数据流

`ContextBuilder` 初始化时加载只读 JSONL。每轮以当前消息检索，按阶段、人物、具体主题、行为兼容、表达强度和真实关系过滤，再限制数量与字符预算。

回复请求增加 `character_knowledge`，其中的 `facts` 和 `dialogue_examples` 与 `selected_memories`、`recent_history` 分开。Planner 只获得相关剧情背景，不获得对白范例；生成回复时才提供匹配的原句、原场景、原受话者、来源与使用限制。小说条目的 ID 不进入用户 `memory_ids`，也不向用户 SQLite 记忆库批量写入小说资料。

默认每轮最多3张剧情卡、3条对白，整个角色检索 JSON 最多6000字符；超预算丢弃整张卡，不截断 JSON 或原句。检索使用本地规则、中文双字片段与具体短语，不增加 LLM、Jev 或 embedding 请求。上下文增加仍会增加已有模型调用的 token 用量。

默认 `integrity_knight` 不检索现实世界记者会、机械身体和 Unital Ring 后期条目。`later_canon` 是显式的后期资料开关；切换后仍没有童年亲历记忆，且不是严格的逐章时间线模拟器。原著人物的历史目标不自动成为当前待办事项。

## 配置与升级

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| novel_context_enabled | true | 使用本地小说检索；关闭仍保留骑士身份与记忆规则 |
| novel_context_dir | 空 | 使用内置 data 目录；可指定相同格式的只读资料目录 |
| novel_context_stage | integrity_knight | 后期资料需显式选择 later_canon |
| novel_fact_limit | 3 | 0～4张剧情卡 |
| novel_dialogue_limit | 3 | 0～4条对白参考 |
| novel_context_max_chars | 6000 | 1000～12000字符，仅计算新增检索 JSON |

升级后重载插件生效。原先持久化的普通生活默认画像，仅在背景、兴趣、作息和事件种子与旧默认完全一致时，在内存中使用新的骑士默认；有意自定义的画像保留，不改写实例配置。角色核心记忆边界仍优先于自定义兴趣。每日事件的自定义种子、默认模板和模型扩写均防止生成童年记忆恢复事件。

资料缺失、过大或损坏时保持聊天可用，不补造检索结果。当前实现不包含向量搜索，对未收录的表达可能漏召回；这是为了避免由宽泛 tag 召回错误情境而采用的保守选择。

## 验证和复现

本地回归覆盖角色记忆边界、童年与听闻区分、宽泛标签不召回、具体场景命中、阶段过滤、调侃关系限制、Planner行为兼容、上下文预算、坏数据回退、旧默认画像迁移和每日事件回归。模拟 AstrBot 私聊 Handler 的实际回复请求携带资料，仍只调用感知、规划、回复三个既有模型阶段。

来源验证见 `novel_source_verification.json`：28条对白逐字核对、747处证据片段逐行核对，源文件 SHA-256 一致。这验证字面来源与导入边界，不证明所有语义概括均无误，也不证明真实 LLM 的多轮角色质量。

需要从原压缩包重建时，在插件目录执行：

```powershell
python scripts/import_novel_context.py <全章覆盖版.zip路径> --output alice_agent/knowledge/data
python scripts/verify_novel_context.py alice_agent/knowledge/data <全章覆盖版.zip路径> --novel <原小说TXT路径>
```

脚本只读取指定成员与数据，不解压执行压缩包中的脚本；重建会覆盖目标 data 目录的三份导入文件。自定义内容应先备份或放在独立目录。资料随v0.9.1发布；未重载服务器生产实例或进行真实 QQ／付费模型验收。
