# 主动重试与每日事件时段（v0.9.4）

下述重试与时段机制始于0.9.3；0.9.4将其中的未回复保护改为有限等待和滚动次数限制，
详见 [PROACTIVE_UNANSWERED](PROACTIVE_UNANSWERED.md)，不再要求一次未回复后必须等到用户发言。

本版修复的日志场景是：允许时段开始时尝试次数0/5，评分和当天抽签通过，
Jev未返回有效决策，随后尝试次数1/5、唯一事件却不再可选。原因是旧版把
技术失败和明确拒发共用了一次性事件标记，不是夜间检查耗尽了五次额度。

## 技术失败与有效决策

- Jev超时、连接错误、HTTP失败、返回解析/数值校验失败属于技术失败。事件释放为可重试，当前轮不绕过Jev直接发送。
- 默认等待60秒，连续技术失败依次等待120、240秒，最长900秒；两项等待可配置，范围1–3600秒，上限不小于首次等待。
- 技术失败仍消耗一次 `proactive_daily_attempt_limit`，不退款。到达上限后当天不再调用，避免每30秒重试持续故障的接口。
- 有效的拒发、暂缓、置信度不足或发送条件不满足保留原规则，不作为技术故障反复重问模型。
- shadow模式的Jev失败继续原有Planner路径，不改为拦截；成功分享和部分分享仍遵守未回复保护、冷却及滚动24小时预算。
- 每次重试重新检查时段、活跃状态、未回复、冷却、评分及剩余尝试；当日概率结果复用，正反结果都不重新抽签。

## 计数、占位和重启

`alice_autonomy.db` 新增 `daily_proactive_attempt_leases`，只保存事件标识、所有者、期限、
失败类型和下一次重试时间，不保存提示词或聊天正文。占位与尝试加一在同一SQLite事务中。
占位至少五分钟，并随配置的模型超时预算增加。正常取消完成本地释放；异常退出由
后续Tick在期限后恢复并安排退避。恢复不退还已经消耗的尝试。

旧任务不能释放新任务的占位，失去所有者资格后不能继续生成/发送；已发送事件不可再释放。
明确跟进把重试状态放在原调度记录metadata内，技术失败不立即把跟进标为完成，
同一跟进最多三次调用尝试，超过有效期不再重试；这些次数不占每日事件分享的计数。
读取 `/alice-status` 只查看缓存与重试状态，不执行恢复、重试、抽签或模型调用。

## 每日事件调用时段

后台Tick先做允许时段、活跃会话、主动开关和未回复等检查，再读取/生成事件。
服务层也检查 `proactive_window_start` / `proactive_window_end`，因此普通聊天入口
不会在时段外新生成每日事件；普通聊天自身的感知、规划、回复不受此时段限制。

当天已有事件可以在时段外只读复用。没有缓存时暂缓，保持“尚未生成”，不写入空批次
冒充当天没有事件，也不消耗主动尝试或生成当天抽签。
事件扩写、Jev反应和模型反应每次调用前复检；已在允许时段开始的请求可能在时段外结束，
此时不再启动后续事件模型或日常主动阶段。跨日完成的旧批次不写回旧日期，下一日正常生成。
使用服务器/容器本地时间，支持跨午夜时段。

每日事件数量是0到配置上限的随机有界批次，`daily_event_max=2`不保证生成两件事。
每日事件相关心情更新可能推迟到允许时段；普通时间衰减与休息驱动继续运行，数值公式不变。

## 升级与旧记录

升级前停止插件并备份原配置及插件数据目录，更新/重新安装后重载。新表为附加结构，
既有发送、冷却、计数和当日抽签保留，不能为触发重试删除数据库或重抽概率。

0.9.2的已尝试记录未保存“技术失败还是有效拒发”，不能仅依据cancelled推断原因。
升级不会自动清零或释放这些旧事件；旧记录当日保持已尝试，下一日的新记录使用新机制。
这避免把原本明确拒发的事件改成重复发送。后续若要恢复某条旧事件，需另行核对其失败证据。

真实供应商恢复、模型质量和QQ送达仍需实际验收。有限重试能处理暂时故障，不能修复错误密钥、
权限、持续限流或供应商服务故障；日志中的 `failure_reason` / `http_status` 用于区分这些情况。
