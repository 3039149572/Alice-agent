# 记忆管理、保留期限与交付恢复

本地候选版 v0.10.0；以下行为已接入源码，部署状态和验收证据以 `REPAIR_PROGRESS.md` 为准。

## 私聊命令

所有命令只使用消息适配器提供的调用者身份，不接受目标用户ID。`local_memory_scope=user` 管理该用户的记忆；`session` 还限制为当前会话。命令不注册主动会话、不调用模型、不把命令保存成聊天记忆。

| 命令 | 行为 |
|---|---|
| `/alice-data list [页码]` | 每页10条当前记忆及完整ID；不把被替代事实混成当前事实。 |
| `/alice-data journal [页码]` | 查看自己的原始轮次；每项文本截断展示，原库内容不被展示截断改写。 |
| `/alice-data show ID` | 内容、最近20条版本/来源/编辑历史。来源表示用户陈述，不能证明现实真实性。 |
| `/alice-data correct ID 新内容` | 更正当前事实须为同类型的一条明确自述；生成新版本。普通原句更新内容和索引，并保存编辑历史。 |
| `/alice-data delete ID` | 预览删除；事实会删除该事实的全部版本、来源、对应原始轮次和索引。 |
| `/alice-data clear-memory` | 预览清空范围内长期记忆和原始轮次。 |
| `/alice-data confirm 确认码` | 5分钟内、同一用户同一会话、单次使用；数据或来源变化后须重新预览。 |

例如，先用 `list` 获取居住地事实ID，再用 `correct ID 我现在住在上海。` 更正。不能用居住地ID改写另一种事实，也不能直接修改已失效版本。

纠错和删除还会清空相关近期会话快照、话题文字、每日摘要与派生主动规划缓存，并删除能识别为调用者所有的本插件诊断JSON。用户范围会涵盖登记过的其他会话，包括不活跃会话；会话范围只处理该会话。待处理旧回复会失效，避免删除后继续发送或写回旧内容。其他用户的数据不进入管理结果。

关系数值、情绪数值、每日事件已应用日期、主动限额和冷却保持原值；这是记忆管理，不是重置互动规则。小说静态知识不属于用户记忆。平台聊天记录、迁移备份、手工导出、AstrBot/Genie外部日志及无法识别归属的损坏诊断文件不会被这些命令擦除。SQLite逻辑删除也不等于磁盘物理擦除。

## 保留期限

| 配置 | 默认 | 范围 |
|---|---:|---|
| `memory_retention_days` | 0 | 长期记忆；按创建/修改较晚时间计算，固定记忆跳过。 |
| `memory_journal_retention_days` | 0 | 原始轮次；事实和其证据另外受记忆策略控制。 |
| `memory_inactive_fact_retention_days` | 0 | 被替代/迟到版本；按失效时间计算，当前版本和固定版本跳过。 |
| `test_log_retention_days` | 0 | 本插件有效命名的诊断JSON，按文件修改时间计算。 |
| `history_restore_max_age_hours` | 72 | 近期会话快照的有效时限，也会物理清理不再返回的会话快照。 |

0表示保留，不会在升级时自动清空现有库。启用后在初始化和最多每小时执行一次；失败会重试，固定状态读取失败时跳过记忆删除。检查任务每分钟运行，独立于 `agent_loop_enabled` 和 `test_log_enabled`。删除记忆时也清理其来源轮次；因此该轮次可能早于单独配置的原始轮次期限删除。

后台清理失败不会被报成成功。删除记忆、来源、索引与写入清理任务在同一个记忆库事务里完成；元数据、快照和派生缓存清理失败后，任务保留到下次尝试或重启。对应用户的新生成/交付先尝试恢复，避免旧内容复活。

## 交付后的本地一致性

`alice_operations.db` 保存尚未完成的交付意图，明确记录实际交付文本，不保存框架对象、提示词、密钥或完整未发送的生成答案。正常完成后移除文本，只留下摘要和操作标识；这些小型收据以及各库幂等标记用于阻止重复计数，会随对话数量增长，不受原始轮次期限自动删除。

被动回复依次写入状态、关系计数、记忆访问、内容/来源和近期历史。每个累加操作在本库内把变更与幂等标记一起提交；原句使用确定性ID，历史保存交付ID。因此崩溃在“写入成功、总任务尚未完成”之间时，恢复不会重复累加。

主动消息同样恢复冷却/每日送达/行动状态、记忆访问与实际历史。分段被取消时只保存已得到框架成功返回的前缀；不会保存尚未确认发送的后缀。初始化、后台任务及该用户下一次工作前均可恢复；恢复路径不调用模型，也不重发消息。旧待恢复列表在拿到锁后重新核对，防止在其已完成、随后被用户删除后又重放。

这不是多个SQLite文件之间的单一事务，也不是QQ送达回执。进程在平台发送成功但本地交付意图尚未落盘前崩溃，或意图库本身不可写时，无法凭本地恢复证明那条消息的送达/留存；不会据此补发或虚构历史。未完成的意图必须保留并排障，不能为让检测通过而删除。备份时应停止插件，保存全部实例数据库、WAL/SHM相关文件及配置。

## 本地验证

`test_memory_governance.py` 覆盖越权/会话隔离、事实/原句纠错、确认失效、事务回滚、清理重启、取消、固定记忆、独立保留任务和旧批次失效。`test_delivery_recovery.py` 使用多个临时真实SQLite文件，在各关键写入后模拟中断；检查恢复后的计数、访问次数、原句数量、历史前缀和主动冷却只提交一次。网络、收费模型和真实QQ不在这些测试的证据范围内。
